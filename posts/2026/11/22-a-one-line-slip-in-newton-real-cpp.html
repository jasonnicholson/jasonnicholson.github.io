A one-line slip in Newton_Real.cpp

Madsen’s stage test needs the derivative at the previous iterate. Vestermark’s 2002 C++ port stores the function value there instead, which makes the test depend on the units of x.

The Madsen-Reid page on this site ports newton_real from Henrik Vestermark’s Newton_Real.cpp. That file, dated 2002, is a C++ port of Kaj Madsen’s 1973 Newton root finder for polynomials. It is also the file I had several AI models convert to MATLAB in May.

I did not find this myself. The pages in this site’s numerical-methods section were written by AI agents, and I have been having Claude, Anthropic’s AI model, review them. In its review of the Madsen-Reid page, Claude flagged one line that does not do what the algorithm says. It also built and ran every test in this post and drafted the post itself. I am publishing it because the finding holds up, and because Madsen and Reid’s own report and Vestermark’s current code both point the same way, as shown below. Madsen’s method decides when to switch to plain Newton steps using an estimate of \(P''\). That estimate is a divided difference of \(P'\) at two successive iterates. In the 2002 code, the “previous” value is the polynomial \(P\) at the previous iterate instead of its derivative \(P'\). So the code subtracts a derivative from a function value.

This post covers four things:

  • the line itself;
  • why it is wrong;
  • what it costs, which is usually little and occasionally four times the iterations;
  • why fixing the line still leaves double roots unsolved. Vestermark’s current solver already handles that part.

Madsen’s two stages

Each iteration computes the Newton step \(\Delta z = P(z)/P'(z)\) and takes it in one of two stages.

  • Stage 1 checks every step. If \(|P|\) does not increase at \(z - \Delta z\), the method also tries \(z - 2\Delta z,\ z - 3\Delta z, \dots\) and keeps the best point. Near a root of multiplicity \(m\), the best point is about \(z - m\,\Delta z\), the multiplicity-corrected Newton step, which converges quadratically. This is how Madsen’s method keeps quadratic convergence at multiple roots. If \(|P|\) increases instead, the step is halved.
  • Stage 2 takes plain Newton steps with no checks. Near a simple root that is the fastest option. Near a multiple root, plain Newton converges only linearly.

The switch to Stage 2 rests on a theorem of Ostrowski. Newton’s method converges from \(w\) if

\[ 2\left|\frac{P(w)}{P'(w)}\right| \max_{z \in K} |P''(z)| \le |P'(w)|, \]

where \(K\) is the disc with centre \(w - P(w)/P'(w)\) and radius \(|P(w)/P'(w)|\). Madsen replaces the maximum by \(|P''|\) at the current iterate. He estimates \(P''\), at no extra cost, by the divided difference of \(P'\) between the previous and current iterates. Vestermark’s description of the test, in section 6.3 of his current paper, is the one followed here:

\[ P''(z_k) \approx \frac{P'(z_{k-1}) - P'(z_k)}{z_{k-1} - z_k}. \]

Stage 2 is used when the previous step was a plain Newton step and

\[ \rho_k = \frac{2\,|P(z_k)|\,|P'(z_{k-1}) - P'(z_k)|}{|P'(z_k)|^2\,|z_{k-1} - z_k|} \le 1 . \]

The ratio \(\rho\) is dimensionless. If you rescale \(x\), or multiply \(P\) by a constant, \(\rho\) does not change. That is the property the code loses.

The line

In newton_real, the variables fz and fz1 hold \(P(z_k)\) and \(P'(z_k)\). The variables f and u hold \(|P(z_k)|^2\) and \(|P'(z_k)|^2\). fz0 and z0 are meant to hold \(P'\) and \(z\) at the previous iterate. The relevant lines, quoted from the file with Claude’s comments marked <-, are:

z0 = complex<double> (0);
fz0 = complex<double> ( a[ n - 1 ] );        // <- P'(0): correct for z0 = 0
...
u = feval( n - 1, a1, z, &fz1 );             // <- fz1 = P'(z_k), u = |P'(z_k)|^2
...
fwz = fz0 - fz1;
wz = z0 - z;
f2 = ( fwz.real() * fwz.real() + fwz.imag() * fwz.imag() ) / ( wz.real() * wz.real() + wz.imag() * wz.imag() );
stage1 = f2/u > u/f/4 || f != ff;
...
z0 = z;
f0 = f; fz0 = fz;                            // <- fz = P(z_k), not P'(z_k)

All three magnitudes are squared, so f2/u > u/f/4 is exactly \(\rho_k > 1\), with f != ff covering “the previous step was not plain”. The test is right as written, provided fz0 holds the previous derivative.

Before the loop it does. a[n-1] is \(P'(0)\), and the previous point z0 is the origin. Inside the loop, fz0 = fz overwrites it with \(P(z_{k-1})\). So from the second iteration on, the code uses

\[ w = P(z_{k-1}) - P'(z_k) \qquad\text{instead of}\qquad P'(z_{k-1}) - P'(z_k). \]

fz0 is used nowhere else in the routine, so the fix is one token:

f0 = f; fz0 = fz1;

Why it matters: units

If \(x\) has units, \(P'\) has the units of \(P\) divided by those of \(x\), so \(P(z_{k-1}) - P'(z_k)\) adds quantities with different units. To see the effect without units, substitute \(x = s\,t\) and solve \(Q(t) = P(s\,t)/s^n\) instead. It is the same problem, with roots \(t = x/s\). Madsen’s ratio \(\rho\) is the same for \(P\) and \(Q\), but the code’s version is not.

Close to a root, \(P(z_{k-1})\) becomes negligible beside \(P'(z_k)\). The code’s test then reduces to \(2|\Delta z_k| \le |\Delta z_{k-1}|\), “the new Newton step is at most half the last one”. Farther out, the \(P\) term can be any size relative to \(P'\), depending on \(s\).

Example: a double root

The page’s Case 2 polynomial is \(P(x) = (x-1)^2(x+2) = x^3 - 3x + 2\). Start it at \(x_0 = -0.7\), with the step limit \(r_0 = 3.5\) that a start of \(-0.7\) gets on that page. (From the start point newton_real picks for itself, this polynomial reaches the double root in 4 iterations under every version in this post.)

The first iteration is a Stage-1 step to \(1.7556\), which is a plain step and passes the stage test, so the second step is plain Newton in both versions. After that the two versions split.

  • Published code: at \(z = 1.412\), the code’s \(\rho\) is 0.32, so the iteration stays in Stage 2. Plain Newton then halves the error at every step, and \(\rho\) creeps toward 1 from below: 0.65, 0.82, 0.91, …, 0.999990, 0.999997. It first exceeds 1, at 1.00001, in iteration 21, and one lengthened step ends the search.
    • Result: 21 iterations, stages 1, 2 (×19), 1. Final error \(3.5 \times 10^{-11}\).
  • Corrected code: at the same \(z = 1.412\), \(\rho = 1.24\). The iteration returns to Stage 1, where the doubled step wins every time. The errors go \(0.41 \to 2.3 \times 10^{-2} \to 9.1 \times 10^{-5} \to 1.4 \times 10^{-9}\), which is quadratic convergence.
    • Result: 5 iterations, stages 1, 2, 1, 1, 1. Final error \(1.4 \times 10^{-9}\).

Both final errors are near the \(\sqrt{\varepsilon}\) accuracy a double root allows in double precision.

Now repeat the same problem in rescaled form, \(Q(t) = P(s\,t)/s^3\) started at \(t_0 = -0.7/s\):

\(s\) Published: iterations (stages) Corrected: iterations (stages)
0.01 5 (11111) 5 (12111)
0.1 5 (11111) 5 (12111)
0.5 21 (12222222222222222221) 5 (12111)
1 21 (12222222222222222221) 5 (12111)
2 20 (1222222222222222221) 5 (12111)
10 5 (12111) 5 (12111)
100 5 (12111) 5 (12111)

The corrected code makes the same decisions at every scale. The published code’s decisions depend on the units of \(x\), and the slow run happens only for \(s\) near 1. That is the scale where \(P(z_{k-1})\) and \(P'(z_k)\) are similar in size and partly cancel.

Fixing the line does not fix double roots

For a root of multiplicity \(m\), write \(e = z - \zeta\). Then \(P \approx c\,e^m\), and the exact ratio tends to

\[ \frac{2\,|P|\,|P''|}{|P'|^2} \to \frac{2(m-1)}{m}. \]

  • Simple root (\(m = 1\)): the ratio goes to 0 and the test passes, as intended.
  • \(m \ge 3\): the ratio is at least \(4/3\), the test fails, and the iteration stays in Stage 1 with its lengthened steps.
  • Double root (\(m = 2\)): the ratio is exactly 1.

So at a double root, the error of the divided difference decides the test, and that error changes sign with the side the iterates come from. Start the same polynomial at \(x_0 = -0.3\) and the iterates approach the root from below: 0.752, 0.882, 0.942, ….

The corrected test now sits just under 1 (0.89, 0.95, 0.98, …, 0.999994). The corrected code takes 18 iterations, 16 of them in Stage 2. The published code happens to fail its test at \(z = 0.882\) (\(\rho = 1.16\)) and takes 5.

Vestermark has already found and fixed this part. Section 6.9 of his Practical Implementation of Polynomial Root Finders (version 8, 26 October 2026) gives the same \(2(m-1)/m\) expansion. It shows a double-root search that takes 22 iterations, mostly in Stage 2, on \((z-2)^2(z-1)(z-3)(z^2+1)\). Since version 01.40, his solver applies a safety factor of 2: it requires \(4\,|P|\,|P''| \le |P'|^2\), which is \(\rho \le 1/2\). A sufficient condition with a margin is still sufficient, and a double root’s ratio of 1 now fails, so the search stays in Stage 1. In newton_real the margin is a second one-line change:

stage1 = f2/u > u/f/16 || f != ff;

Claude built three versions of the 2002 file: as published, with fz0 = fz1, and with both changes. They reproduce his numbers, 22 iterations without the margin and 5 with it:

How much does it cost in practice?

The examples above are single searches chosen to show the effect. For a broader view, Claude ran the three versions on two sets of 200 random real polynomials of degree 4 to 30, with the polynomial coefficients drawn from \(N(0,1)\):

  • Set A: random polynomials as drawn.
  • Set B: a random polynomial of degree 2 to 28 multiplied by \((x - r)^2\), with \(r\) uniform on \([-2, 2]\), so every polynomial has a real double root.

The reference roots came from mpmath.polyroots at 60 digits. A root’s error is measured relative to \(\max(1, |\text{root}|)\). Each polynomial was solved once, from newton_real’s own start point.

Published fz0 = fz1 fz0 = fz1 and margin
Set A, total iterations 13 365 13 339 13 335
Set A, largest relative root error \(1.8 \times 10^{-13}\) \(1.8 \times 10^{-13}\) \(1.8 \times 10^{-13}\)
Set B, total iterations 14 889 14 932 14 145
Set B, root searches with 10 or more Stage-2 steps in a row 55 61 0
Set B, searches stopped by the 50-iteration limit 1 0 0
Set B, median of the largest relative root error \(7.8 \times 10^{-9}\) \(8.1 \times 10^{-9}\) \(7.8 \times 10^{-9}\)

Next, Claude rescaled every polynomial exactly with \(s = 1/64\), \(8\) and \(1024\). These are powers of two, so the rescaled coefficients carry no rounding. Then it counted the polynomials whose sequence of stage decisions changed:

Rescaling Published fz0 = fz1 fz0 = fz1 and margin
\(s = 1/64\), set A / set B 197 / 198 3 / 35 3 / 15
\(s = 8\), set A / set B 64 / 101 5 / 36 5 / 15
\(s = 1024\), set A / set B 71 / 102 5 / 33 5 / 13

Claude has not traced the few changes left in the corrected versions. They are rounding effects. For example, the start point is computed with logarithms and exponentials, so it does not scale exactly, and in set B a double root’s ratio of 1 can tip either way.

So the slip is real but mostly harmless:

  • It moves the stage decision in most polynomials whenever the units of \(x\) change.
  • It does not change the roots or their accuracy.
  • On these sets, correcting it changes the total iterations by 0.2% (set A, fewer) and 0.3% (set B, more).

It can still cost a lot in a single search, as the 21-iteration example shows. At double roots, the larger effect is the borderline test itself, which only the margin removes: with it, set B needs 5% fewer iterations and no long Stage-2 runs.

Back to quadratic convergence at multiple roots

Madsen’s lengthened steps do converge quadratically at multiple roots, as long as the iteration stays in Stage 1. The stage test decides whether it does.

  • Published code: the decision depends on the units of \(x\).
  • Corrected derivative: the decision is right for \(m \ge 3\) and a coin toss at \(m = 2\).
  • Corrected derivative with the factor-2 margin: Stage 1 is kept at every multiple root.

Which version to use

  • Newton_Real.cpp, 2002: the file on hvks.com still has fz0 = fz. Any port of it carries the same line unless the port changed it. That includes the MATLAB conversions in my May post and the scripts behind this site’s Madsen-Reid page, which says so.
  • C++ listings in his Fast Polynomial Root Finder papers, Parts One and Two (October 2023): these write the divided difference with the previous derivative, p1zprev. In the printed listings, though, p1zprev is set to \(P'(0)\) before the loop and is not updated inside it.
  • His current reference, the JavaScript of the web solver: this is what version 8 of the paper describes. It stores the derivative (fz0=fz1) and applies the factor-2 margin.

If you use the 2002 file, make both one-line changes.

Reproducing this

All the numbers above come from the published file compiled with g++. Claude used three scratch copies of it, edited only on the two lines shown, plus a small driver.

  • Building on Linux: stdafx.h can be an empty header that defines _DBL_RADIX as FLT_RADIX. The file uses the register keyword, so compile with -std=c++14.
  • Forcing a start point: the forced starts reset z, dz, f and r0 after the line r0 = 2.5 * u;, which leaves z0 and fz0 at their initial values.
  • Counting: iteration counts are the loop’s itercnt for each root search. The random sets use NumPy’s default_rng(20261122).
