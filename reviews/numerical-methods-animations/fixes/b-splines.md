### F1 — resolved
- Evidence: The sentence "has local support over exactly 4 knot spans" is gone. It now says $N_{i,4}$ "is zero outside $[t_i, t_{i+4}]$, which is at most 4 knot spans", and that the clamped vector (0,0,0,0,1,2,3,4,4,4,4) gives 1, 2, 3, 4, 3, 2, 1 non-zero spans, with only $N_{4,4}$ covering all 4. `verify.py` with scipy `BSpline.basis_element(t[i:i+5])` on a 200001-point grid gives supports [0,1], [0,2], [0,3], [0,4], [1,4], [2,4], [3,4], and non-zero-length spans 1, 2, 3, 4, 3, 2, 1. With 1-indexed knots (t_1..t_11, matching the script's `t_knots[i:i+k]` and the page's $N_{1,4}..N_{7,4}$), [t_i, t_{i+4}] is exactly these intervals. The last frame of bsplinebb.gif (bb/frame_007.png) shows N_1 vanishing at t=1, N_7 starting at t=3, and N_4 spanning 0–4, which agrees.

### F2 — resolved
- Evidence: The Description now defines the curve by order $k$ (degree $k-1$), writes $C(t)=\sum_i P_i N_{i,k}(t)$, and adds "Cubic B-splines have order k=4, so their basis functions are written $N_{i,4}$." That matches the scripts (`k = 4`, 11 knots = 7 + 4) and the GIF labels $N_{i,4}$. scipy confirms the curve is degree 3: `S.derivative(4)` is rejected because the spline order is k=3 (scipy uses degree). At knots 1, 2 and 3 the second derivative is continuous (jumps ≤ 1.6e-6 with a ±1e-7 one-sided difference, which is the step size), and the third derivative jumps by 41.5, 24.0 and 31.5. So the curve is piecewise cubic and C². No text that is still on the page uses the subscript as the degree.

### F3 — resolved
- Evidence: The alt text now reads "traced from 7 control points by summing Cox–de Boor basis functions; it passes through only the first and last control points and lies within the convex hull of the control polygon". bsplineaa.jl lines 11–32 compute $\sum P_i N_{i,4}(t)$ using the Cox–de Boor recursion, so the description is correct. Minimum distance from each control point to the curve (scipy): (0,0) 0; (1,2) 0.976; (2,-1) 1.211; (3,2) 0.912; (4,-0.5) 0.911; (5,1.5) 0.680; (6,0): S(4) = (6,0) exactly. So the curve passes only through the end points. All curve samples lie inside the convex hull (Delaunay test True), and the partition of unity holds to an error of 4.4e-16. bsplineaa.gif frame 31 shows the same picture.

### F4 — resolved
- Evidence: The header comment now says "Traces the curve continuously as t runs from t_min to t_max; control polygon shown throughout". The knot comment now says "k copies of t_min, interior knots, k copies of t_max". The code uses `t_vals` from t_min+1e-9 to t_max−1e-9 and 31 frames at frac = frame/30.
