# Verification: adams-bashforth-moulton-method
## A1 — confirmed
- What I checked: Re-ran a copy of the committed script (verify/copy.jl, output to verify/copy.gif) and wrote my own ABM4 PECE (RK4 start) in Python (verify/check.py), comparing against a scipy DOP853 reference (rtol 1e-13). I ran a convergence study over N = 50…800 and computed the real-axis absolute-stability boundary of ABM4 PECE (verify/stab.py). I looked at committed frames 049 and 051.
- Evidence:
  - The Julia copy and my Python agree to about 1e-15. ABM y(5) = 0.138090; the reference y(5) = 0.0081199 (DOP853), and the script's own RK4 h=1e-4 gives 0.0081199. So the final value is about 17x the true value.
  - The error stays ≤ ~1e-6 up to t≈2.6. After that it oscillates in sign with growing amplitude: +1.4e-4 (t=3.3), -4.4e-4 (3.7), +7.3e-4 (4.0), -4.5e-3 (4.5), -1.1e-2 (4.8), +2.2e-2 (4.9), +0.130 (5.0). y_48 = -0.001831 at t=4.8 is negative while the true value is +0.0092.
  - Cause: the local Jacobian is ∂f/∂y = -t/(3 y^{2/3}). h·∂f/∂y passes -1.0 at t≈3.3 and reaches -4.1 at t=5. My computed real stability interval for ABM4 PECE is about (-1.285, 0). The step h=0.1 is therefore outside the stability region from t≈3.4 onward, because the problem becomes stiff as y→0.
  - The code is not buggy. The predictor and corrector coefficients (55,-59,37,-9)/24 and (9,19,-5,1)/24 are correct, and the RK4 start is correct. With N=100, max error is 8.5e-6. Max error then falls by factors of about 28 and 23 as N doubles further (about 4th order), and the solution stays positive. The instability is a real property of the method at h=0.1 on this problem.
  - Frames: frame_049 (y_48) shows the red marker sitting on the y=0 axis, clipped at ylims (0, 1.55), below the dashed reference. frame_051 (y_50) shows a clear upturn of the magenta curve to about 0.14 at t=5, away from the dashed reference near 0.008. Because the y-range is 0–1.55, the oscillation from t=3.3 to 4.7 is too small to see; only frames ~49–51 show the problem.
- Severity: Error is fair. Line 33's "smooth and stable descent toward the right endpoint" is false: the last frames show the curve hitting zero and turning up, which a reader can see. Line 32's "tracks the reference closely over the full interval" is false near t=5, with a 1600% relative error in y(5). It is true for t ≲ 4.7 at plot scale.
- Correction to the allegation (if any): None material. The "oscillating error that grows" is visible only in the numbers, not at the GIF's plot scale; the GIF shows only the negative dip and the final upturn (last ~3 frames).
